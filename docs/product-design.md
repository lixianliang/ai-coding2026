# 产品设计

## 产品形态

一台 `yunliao-s3` 放在桌上，多人围坐共玩。玩家之间直接讨论，设备只在需要向 AI 提问、猜测汤底或发出游戏控制指令时收音。固定房间为 1、2、3，每个房间同时只允许一台设备。

首版不做多设备远程房间、玩家音频转发或混音、独立声纹注册、AI 玩家、真人主持和掉线续局。

## 一局游戏流程

```text
玩家说“进入 2 号房玩海龟汤”
        ↓
Linx 识别意图并调用设备 MCP
        ↓
设备关闭 Linx 连接，进入 Go 游戏服务
        ↓
播放欢迎语，等待“开始游戏”
        ↓
AI 播报汤面，玩家现场讨论
        ↓
BOOT 开始 manual 收音；再次按下结束并提交
        ↓
ASR 转写 → AI 判题 → TTS 播报
        ↓
猜中或 10 分钟到时，播报固定汤底和结算
        ↓
“游戏继续”开始下一局；“退出游戏”关闭游戏连接并恢复 Linx
```

进入房间不会自动出题。玩家说“开始游戏”后才从题库取题并朗读汤面。

## 交互规则

- AI 播报期间设备处于 speaking，BOOT 不开启收音。
- 题面播报后，玩家可直接讨论；普通讨论不上传、不判题。
- 需要提问、猜汤底或发出“开始游戏 / 游戏继续 / 退出游戏”等控制指令时，按一次 BOOT 开始收音，再按一次结束。
- 服务端只处理一次 manual start 和 stop 之间的音频。stop 后等待 ASR final，再进行控制指令识别或判题。
- 说“再说一遍汤面”“重复一下汤面”会重播当前题面，不计分、不判题。
- 每次收音最长 60 秒；每局最长 10 分钟。
- 猜中或超时后播报固定汤底和冠军，进入讨论态，不自动开下一局。
- 讨论态提交“游戏继续”或“开始游戏”才会开始下一局；“退出游戏”会离开房间。

## 判题和积分

判题模型只返回结构化 verdict，固定汤底始终来自服务端题库：

| verdict | 含义 | 积分 |
| --- | --- | ---: |
| `yes` | 问题答案为是 | +1 |
| `close` | 接近关键事实 | +2 |
| `correct` | 猜中汤底 | +5 |
| `no` | 不是 | 0 |
| `irrelevant` | 与汤底关系不大 | 0 |

豆包 ASR 在同一连接内返回说话人编号，Go 按本局首次提问顺序映射为“玩家 1、玩家 2、玩家 3”。无法确认唯一说话人时照常判题，但不计个人分。积分只在本局有效，同分时猜中者优先，再按首次发言顺序。

## 结算和展示

Go 提供结算页，门店可用电视或平板打开：

- `GET /scoreboard?room_id=1`：结算页，每 2 秒刷新；
- `GET /v1/rooms/{room_id}/scoreboard`：统一响应格式的只读数据接口。

进行中显示实时积分；结束后显示汤面、汤底、冠军和玩家排名。设备只播报冠军和固定汤底，不播报完整排名。

## 功能边界

### 首版包含

- Linx 入口对话、设备 MCP 和 Game WSS 切换；
- 固定房间、单设备共享、欢迎语和显式开始；
- manual 收音、ASR、结构化判题、固定汤底 TTS；
- 重播汤面、单次收音和整局超时；
- 说话人编号、积分、结算页和自然语言继续/退出。

### 首版不包含

- 匹配或排队大厅；这里的“等待”只是设备进入指定房间后的开局等待状态；
- 多设备同房、玩家语音转发、远程混音；
- 实名声纹注册、AI 玩家和真人主持；
- 掉线快照、断线续局和跨局长期排行榜。

## 演示脚本

1. 说“进入 1 号房玩海龟汤”，播放欢迎语。
2. 按 BOOT 说“开始游戏”，播放汤面。
3. 玩家现场讨论，按 BOOT 提问，得到“是 / 不是 / 接近”。
4. 猜中后播放冠军、固定汤底和结束提示，打开结算页。
5. 按 BOOT 说“游戏继续”开始下一局，再演示“退出游戏”。
