# Demo 视频：录制与上传

**视频状态：待录制、待上传。** 录制后在此处和仓库首页补上可访问的视频链接。建议交付约 3 分钟展示版，同时保留完整游戏原片。

## 1. 最简单的录法

- 手机横屏，1080p、30 fps，支架固定；镜头同时包含设备屏幕、BOOT 按键和两位玩家。手机原声录入玩家和设备扬声器，先试录 10 秒确认能听清。
- 电脑打开同房间结算页，macOS 按 `Shift + Command + 5` 录屏，用于插入排名和架构/评测画面。电脑不播放另一份主持音频，避免双声。
- 如果用 OBS 合成画面，添加摄像头、浏览器窗口和一个麦克风音源；全程保持设备原声，不用后配 TTS 代替现场回复。
- 从入房录到退出，先留一份连续原片。展示版可剪掉讨论空档并标注剪辑，关键提问、等待、回复和局终播报保留完整；超过 3 分钟就优先压缩解说。

## 2. 录制前准备

1. 按[交付说明](../project-delivery.md#2-从源码运行)启动 Go 服务，确认设备与服务端网络互通、Linx 已绑定，游戏地址正确。
2. 打开 `http://127.0.0.1:8080/scoreboard?room_id=1`；设备也进入 1 号房。
3. 在本地 `config.local.json` 中仅保留示例题 101（火柴与冰）和 102（电梯与雨伞），结束旧游戏后重启。选题是随机的，录制时按实际汤面选下表对应台词；不修改数据库强行宣称自然猜中。
4. 记录当前提交 SHA、日期和模型名；如要展示评测结果，提前真实运行命令并保留输出，不能展示写死的 PASS 图片。
5. 录屏避开密钥配置、控制台 token 和设备个人信息。当前声纹聚类需真人验收，若出现编号错误保留记录并修复，不剪成“识别正确”。

## 3. 逐步操作与预期

除唤醒/入口外，所有指令均为：**按一下 BOOT → 一位玩家说话 → 再按一下 BOOT → 等完整回复**。AI 正在播报时不按键。

| 顺序 | 操作 / 台词 | 要拍到的结果 |
| --- | --- | --- |
| 1 | “你好小智”，等响应，再说“进入一号房玩海龟汤” | 入房欢迎，尚未播汤面 |
| 2 | 按键说“开始游戏” | 完整汤面、屏幕显示；播完回待机 |
| 3 | 玩家 A、B 各提问一次，A 再问一次 | AI 按题意回复；网页核对匿名玩家编号与积分，同一人再次发言不应另建编号 |
| 4 | “再说一遍汤面” | 完整重播当前汤面，不判题、不加分 |
| 5 | 一位玩家说完整推理（见下表） | 猜中、冠军（有有效积分时）、完整固定汤底；网页显示结算 |
| 6 | 停下来讨论几秒 | 不自动开下一局 |
| 7 | “游戏继续” | 开新一局并播不同题面（启用两题时） |
| 8 | 等播完，再说“退出游戏” | 游戏连接结束；设备回待机，再唤醒可回 Linx |

下面是**排练台词**，不是玩家真实推理能力证明；判题结果以实际运行记录为准。

| 汤面 | A 第一次 | B 提问 | A 再提问 | 猜底陈述 |
| --- | --- | --- | --- | --- |
| 火柴掉进水杯却未熄灭 | “杯子里的水是冰吗？”（是） | “火柴是被风吹灭的吗？”（不是） | “火柴落在了能托住它的东西上，对吗？”（接近） | “杯子里的水冻成冰了，火柴落在冰面上，没有碰到液态水，所以没有熄灭。” |
| 晴天坐到十楼、雨天到十二楼 | “这和他的身高有关吗？”（是） | “电梯在晴天坏了吗？”（不是） | “雨天带的东西帮助他按按钮了吗？”（是） | “他个子矮，平时只能按到十楼；下雨带伞，就用伞尖按到十二楼。” |

首次编号按本局有效提问出现顺序分配。欢迎、开始等指令不用于证明玩家积分正确；如果 ASR 返回混合说话人或无编号，按现有规则不计个人分。

## 4. 约 3 分钟展示版

| 时间 | 画面 | 解说重点 |
| --- | --- | --- |
| 0:00–0:15 | 一桌玩家、一台设备 | “面向桌游店和剧本杀店，替代海龟汤的一段主持工时，也能作为随时开玩的增值体验。” |
| 0:15–0:45 | Linx 入房、欢迎、显式开始、汤面 | 入口和 Go 游戏服务分工；不自动开局 |
| 0:45–1:35 | 轮流提问、简短现场讨论、汤面重播 | 玩家无需报名字，AI 理解问题；玩家面对面交流 |
| 1:35–2:15 | 猜底、完整揭晓、结算页 | 固定汤底不被模型改写，匿名积分与冠军可查看 |
| 2:15–2:40 | 讨论、继续下一局、退出 | 玩家决定游戏节奏；保留实际响应时间 |
| 2:40–3:00 | 架构图 + 一份真实评测/修复 PR | 展示模块边界、评估函数、回归与 skills；“999 元/月”如出现须注明定价假设 |

完整原片可更长。此脚本覆盖猜中结束分支，不证明 10 分钟超时、掉线或噪声环境全部验收通过；其他回归用测试证据说明。

## 5. 上传 GitHub

建议展示版命名 `turtle-soup-demo.mp4`（H.264 视频 + AAC 音频）。优先放本目录并通过 PR 上传：

```bash
git switch -c codex/demo-video
# 将视频复制到 docs/demo/turtle-soup-demo.mp4
# 更新本页与根 README 的视频链接、录制日期和对应代码 SHA
git add -- docs/demo/turtle-soup-demo.mp4 docs/demo/README.md README.md
git commit -m "docs: add recorded turtle soup demo"
git push -u origin codex/demo-video
```

再创建 PR。GitHub 普通 Git 文件限制为 100 MiB；建议控制在 50 MB 以下（3 分钟约 1.5 Mbps 视频通常足够），上传前试听字幕、设备声音和画面。较大原片放 GitHub Release 附件，再通过 PR 更新本页链接；不要提交失效的本地路径。最终检查：退出账号或无痕窗口也能访问视频，仓库首页能直达展示版。
