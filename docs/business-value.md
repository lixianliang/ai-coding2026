# 商业价值

## 产品定位

海龟汤是面向桌游店、剧本杀店和独立包间的 AI 主持游戏。一台 `yunliao-s3` 放在桌上，玩家围坐共玩；设备负责讲题、听取向 AI 的提问、判题、公布汤底和展示结算结果。

产品替代的是一段可重复的主持工作，不是整名店员。门店仍需要负责接待、开场、异常处理、其他游戏和售后。产品交付的是“设备 + 题库 + AI 主持 + 结算页 + 运维”，不是单独出售 ASR、LLM 或 TTS 能力。

## 客户和购买理由

付费方是有包间的桌游店、剧本杀店和聚会门店。

- **减少主持排班压力。** 讲题、回答“是/不是/接近”、判断猜中和公布汤底由设备完成，店员可以处理接待和其他桌台。
- **增加低峰时段的可售项目。** 门店在换场、夜间或没有空闲主持时，可以用一台设备快速开局。
- **形成包间体验差异。** 高端门店可以通过主题题库、品牌外壳、音色和结算大屏把产品包装成增值项目。

一台设备服务一个包间；多包间和多门店需要增加设备、部署和运维能力，不能按纯软件订阅估算。

## 成本和收入模型

一局只在明确节点调用云服务：

- TTS 播放欢迎语、汤面、判定、冠军、汤底和结束提示；
- 玩家按 BOOT 收音时使用 ASR，现场讨论不上传；
- 每次提问使用 LLM 做结构化判题；
- 不提供持续闲聊，调用量受 10 分钟单局和 60 秒单次收音限制。

单店贡献可按下式计算：

```text
单局云成本 = ASR 单价 × 收音秒数
           + TTS 单价 × 计费字符数
           + LLM 输入/输出 tokens × 对应单价

单店月贡献 = 订阅收入 + 增量开局分成
           - 云成本 - 设备折旧 - 内容/运维/售后成本
```

当前成本估算只作为工程预算，实际价格和账单以 provider 为准。豆包 ASR 持续会话包含静音保活，不能直接沿用只按玩家说话时长计算的旧估算。TTS、ASR、LLM 的公开价格和计费规则也需要随账单复核。

## 定价假设

以下是待门店验证的价格假设，不是已确认报价：

| 档位 | 目标客户 | 暂定月费 | 交付内容 |
| --- | --- | ---: | --- |
| Lite | 价格敏感的小店 | 499–699 元 | 1 个包间、1 台设备、基础题库、结算页、自助使用 |
| Standard | 普通桌游店/剧本杀店 | 999 元 | 1 个包间、1 台设备、题库更新、远程支持、使用报表 |
| Premium | 高端店或品牌 IP 店 | 1999 元起 | 主题题库、品牌外壳和音色、优先支持；多包间另计 |

按每局为门店带来 120–360 元增量收入的示例，999 元月费需要约 3–9 个增量开局覆盖。这只是单位经济演示，实际应替换为门店客单价、上座率和空档时长。

## 验证计划

建议先部署 3 家门店、连续观察 2 周，记录：

| 阶段 | 指标 | 目的 |
| --- | --- | --- |
| 部署 | 首次可用时间、店员介入次数 | 验证设备、网络、Linx 和 Game WSS 是否容易上线 |
| 使用 | 每日开局数、完整完成率 | 验证真实需求和主持稳定性 |
| 复玩 | “游戏继续”比例 | 验证体验是否支持连续消费 |
| 质量 | 误判、丢帧、超时、断线 | 验证是否影响现场节奏 |
| 成本 | TTS 字符、ASR 秒数、LLM tokens | 用实际账单校准单局成本 |
| 经营 | 月贡献、回本局数、续费率 | 验证价格假设 |

## 风险边界

- 付费意愿、999 元月费和 3–9 局回本都属于假设，尚无门店样本证明。
- 玩家身份来自 ASR 会话内的说话人聚类，嘈杂、短句和抢话可能导致编号不稳定；无法确认身份时只判题、不计个人分。
- 网络、ASR、LLM 或 TTS 故障会影响现场节奏，需要门店准备人工兜底。
- 内容更新、设备折旧、部署、客服和售后可能比模型调用更影响毛利。
