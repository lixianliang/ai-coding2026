# 海龟汤：产品定位与商业设计

> 一句话：给桌游店、剧本杀店增加一个无需店员主持的语音加购项目。一台设备放在桌上，玩家围坐直接交流，需要问 AI 主持人时按一下 BOOT。

## 1. 产品定义

| 维度 | 当前产品 |
| --- | --- |
| 使用方式 | 线下多人围坐，共用一台 `yunliao-s3` |
| 音频 | 玩家之间直接听见，不经过服务端；设备只负责玩家与 AI 主持人的问答 |
| 身份 | 首版不区分玩家，不做声纹和说话人分离 |
| 操作 | 按 BOOT 开始收音，再按一次结束；AI 播报时设备不收麦 |
| 游戏 | 入房欢迎后由玩家说“开始游戏”；AI 出汤面、判定问题、猜中或超时后朗读固定汤底 |
| 节奏 | 每局 10 分钟；猜中后先讨论，说“游戏继续”才开下一局，说“退出游戏”离开 |
| 目标客户 | 桌游店、剧本杀店、有包间的聚会门店 |
| 首版不做 | 多设备房间、玩家语音转发、声纹、AI 玩家、真人主持人、掉线恢复 |

产品边界必须明确：这不是远程语音社交产品。玩家现场交流的效率本来就高于多设备转发，产品价值是把“店员讲题、判题、公布汤底”这段主持工作自动化，增加门店可售时段。

## 2. 为什么门店需要

- 桌游店和剧本杀店有闲置包间、换场空档和不愿增加的主持排班。
- 海龟汤规则轻，适合 10 分钟一局的短加购；不需要开 App 或发耳机。
- 一台设备即可开玩，部署和售后成本远低于每人一台设备。
- 玩家线下本来就能直接说话，不需要声纹、混音和跨设备音频路由。
- 内容可持续更新，门店可以按房间订阅题库和玩法。

## 3. 商业假设

以下是待门店访谈和真实成本数据验证的假设，不作为已确认价格：

| 项目 | 待验证假设 |
| --- | --- |
| 收费方式 | 门店按房间/月订阅，或按开局次数付费 |
| 硬件 | 门店采购一台设备，接入现有包间 |
| 增量收入 | 换场空档多卖 1 局；不新增店员排班 |
| 内容 | 基础题库 + 定期更新主题题库 |
| 成本 | 设备 BOM、云端单局成本、门店部署和售后 |

核心指标：

| 阶段 | 指标 | 说明 |
| --- | --- | --- |
| 部署 | 一台设备首次可用时间 | 验证设备、网络、Linx 入口和游戏切换 |
| 使用 | 每店每日实际开局数 | 是否真的利用换场空档 |
| 完成 | 一局完整完成率 | 验证 ASR、判题、TTS 和计时稳定性 |
| 复玩 | 同组玩家主动说“游戏继续”的比例 | 验证游戏本身是否值得继续 |
| 经营 | 单店月增量收入 / 设备与云成本 | 验证回本周期 |
| 稳定 | 丢帧、误判、超时、断线率 | 决定门店能否无人值守 |

## 4. 评分维度与现场证据

| 评分维度 | 评委要看到 | 本方案证据 |
| --- | --- | --- |
| 商业价值 & 产品设计 50% | 明确付费方、门店场景和增量价值 | 桌游店/剧本杀店换场加购；一台设备即可部署；玩家现场自然交流；第二局率和单店增量收入可量化 |
| 架构设计 20% | 设备薄、服务端权威、协议简单 | Linx 负责入口，Go 负责游戏；每房一台设备；复用 `hello/listen/tts` 和 Opus；不新增 waiting 状态机 |
| AI 价值呈现 15% | AI 真正承担主持人工作 | Qwen ASR 听懂玩家问题，DeepSeek 按汤底判题，MiniMax TTS 朗读汤面和固定汤底；固定答案不被模型改写 |
| AI 工程效率 15% | AI 参与研发且有回归 | 判题评测集、真实云端语音链路、manual 按键协议回归、计时/继续/退出自动测试；一条命令验证 |

## 5. 3 分钟 Demo

| 时间 | 演示内容 |
| --- | --- |
| 0:00–0:20 | 桌游店换场空档；店内没有空闲主持，桌上一台设备直接开局 |
| 0:20–0:40 | 玩家说“进入 1 号房玩海龟汤”；设备播放欢迎提示，玩家按 BOOT 说“开始游戏”，AI 朗读汤面 |
| 0:40–1:35 | 玩家围坐讨论，先后按 BOOT 向 AI 提问；“是 / 不是 / 接近”由设备播报 |
| 1:35–2:05 | 一名玩家猜中，AI 朗读固定汤底；AI 提示可以先讨论 |
| 2:05–2:30 | 玩家按 BOOT 说“游戏继续”，AI 开新一局；再演示“退出游戏” |
| 2:30–3:00 | 展示单局云端成本、完整完成率、第二局率和门店回本假设 |

现场要证明：玩家之间不需要通过设备说话；设备只承担与 AI 主持人的交互；整局没有店员讲题或判题。

## 6. 主要风险

- 共享一台设备意味着同一时间只有一名玩家向 AI 提问；现场讨论仍可多人同时进行。
- 不做声纹是首版范围控制，不把“识别谁在问”包装成已具备能力。
- 门店网络和 4G 稳定性决定 ASR/TTS 是否可用，必须现场实测。
- 若单局成本和设备维护成本过高，商业模型不成立；先拿真实门店数据再定价。
