# 海龟汤：产品定位与商业设计

> 产品定位：**每位玩家一台设备，远程组成语音房间一起玩**。不是线下单房间共用一个扬声器的“AI 主持机”。

## 1. 两种产品定义

| 维度 | 方案 A：线下单扬声器 | 方案 B：远程多设备 |
| --- | --- | --- |
| 设备 | 房间共用一台，主要当扬声器 | 每位玩家一台 |
| 麦克风 | 共享麦克风，需要声纹/说话人分离 | 每台设备对应一个玩家，设备身份即玩家身份 |
| 音频 | 多人声音混在一起，只从一台设备外放 | 玩家语音转发给同房其他设备，AI 回复发给全房 |
| 使用场景 | 桌游店、剧本杀店，替代店员主持 | 异地朋友、家庭、线上社群随时开局 |
| 产品本质 | 线下门店的自动主持工具 | 语音优先的多人社交游戏终端 |
| 当前决定 | 不做 | **做** |

明确排除方案 A：不做共享单扬声器、声纹识别、说话人分离、门店排班替代。否则硬件数量和产品价值都会被压缩成一台“会说话的音箱”。

## 2. 产品定义

**一句话：不装 App、不拿手机，每个人用一台语音设备远程上桌，由 AI 主持海龟汤。**

- 玩家各自在不同地点，通过 Linx 语音进入 1/2/3 号房。
- 每台设备独立收音、独立播放，房间身份由设备绑定，不依赖声纹。
- 同一时刻只有先起音的玩家获得发言权，其他设备闭麦。
- 发言者的语音实时传给同房其他设备；发言结束后 AI 判定并发给全房。
- 每局结束进入讨论，不自动开下一局；玩家说“游戏继续”后才出新题。
- 首版只做 1～6 个真人玩家和 AI 主持，不做 AI 玩家、真人主持。

## 3. 为什么硬件有存在价值

- **身份确定**：设备就是玩家，不需要从混合音轨猜测谁在说话。
- **远距离可行**：设备只负责自己的麦克风和扬声器，房间音频由服务端转发。
- **交互最短**：唤醒后直接说“我要玩海龟汤”，不用找手机、开 App、组队和配置耳机。
- **产品差异化**：卖的是“实体语音游戏终端 + 房间体验 + 持续更新内容”，不是大模型套壳聊天。

## 4. 商业价值

### 4.1 用户与付费方

- 核心用户：3～6 人异地朋友、家庭、线上社群。
- 首购付费方：愿意为聚会体验购买多台设备的个人或小团体。
- 后续付费点：新题库、新玩法、主题内容包。
- 渠道可能：消费电子品牌、内容社区、运营商/云厂商联合套餐；不把线下门店作为首版主场景。

### 4.2 商业模型假设

先验证，不先定死价格：

1. 设备套件一次性收入：3～6 台起步包。
2. 内容订阅：按房间或账号提供持续更新的题库和玩法。
3. 联合发行：与设备品牌、社区或 IP 方分成。

需要实测后才写价格：设备 BOM、云端单局成本、用户可接受的首购价、内容订阅续费率。

### 4.3 核心指标

| 阶段 | 指标 | 说明 |
| --- | --- | --- |
| 开局 | 3 台设备在 5 分钟内组房成功率 | 验证设备、Linx 入口和选房是否顺畅 |
| 单局 | 完整玩完一局比例 | 验证 AI 出题、抢麦、判题和 TTS 是否形成完整体验 |
| 留存 | 第二局触发率 | 最能区分“玩过一次”和“愿意继续玩” |
| 传播 | 邀请新玩家成功率 | 远程多人产品必须靠房间邀请增长 |
| 复购 | 周活跃房间数、题库消耗量 | 验证内容是持续付费还是只卖硬件 |
| 成本 | 单局 ASR + LLM + TTS + 带宽成本 | 决定订阅价格和毛利 |

## 5. 评分维度与现场证据

| 评分维度 | 评委要看到 | 本方案证据 |
| --- | --- | --- |
| 商业价值 & 产品设计 50% | 用户是谁、为什么现在需要、为什么不是手机 App | 异地朋友开局场景；每人一台设备；无需声纹；第二局率作为核心商业指标；硬件套件 + 内容订阅假设 |
| 架构设计 20% | 多房间可信、设备够薄、协议够简单 | 每房一个 Go actor；服务端权威维护成员、发言权、计时；复用 `hello/listen/tts/Opus`；MCP 只负责入口，不承载音轨 |
| AI 价值呈现 15% | AI 不是套壳 TTS | Qwen ASR + 服务端 VAD、DeepSeek 判定、MiniMax 主持语音；AI 负责出题、判题、结束播报，固定汤底不被模型改写 |
| AI 工程效率 15% | AI 参与研发且可回归 | 判题评测集、完整 TTS→ASR→判定→TTS 链路、多人音频路由/抢麦/继续游戏自动回归、一条命令验证 |

## 6. 3 分钟 Demo

演示必须让评委看到“不同地点的多台设备”，而不是一群人围着一台音箱。

| 时间 | 演示内容 |
| --- | --- |
| 0:00–0:15 | 三位异地玩家，每人一台设备；没有手机 App 和游戏主持人 |
| 0:15–0:35 | 玩家分别对设备说“进入 2 号房玩海龟汤”；AI 向全房朗读汤面 |
| 0:35–1:20 | A 提问，B/C 的设备同时听到 A 的语音；A 说完后 AI 的判定也发给 B/C |
| 1:20–1:50 | 一名玩家猜中，AI 向全房朗读固定汤底 |
| 1:50–2:15 | 玩家继续讨论，再说“游戏继续”；AI 用新汤面开启下一局 |
| 2:15–2:35 | 玩家说“退出游戏”，设备回到 Linx 正常对话 |
| 2:35–3:00 | 展示第二局率、单局云端成本、多人回归结果和后续玩法扩展 |

现场必须证明三件事：玩家语音先被同房其他人听到，AI 判定随后发给全房，第二局由玩家明确触发。

## 7. 产品边界

- 目标形态是远程多设备；同一物理空间使用时可能产生回声，不作为首版优化重点。
- 不靠声纹区分玩家；发言权由 Qwen VAD 的首个起音事件和设备身份共同确定。
- 首版不做 AI 玩家、真人主持、掉线快照恢复和复杂大厅。
